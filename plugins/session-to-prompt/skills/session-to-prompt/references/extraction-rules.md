## 1. 다섯 칸 판정 기준

### 1) 최초 지시

작업을 처음 요구한 사용자 발화 하나. 인사말이나 맥락 설명이 앞에 붙어 있으면 요구에 해당하는 문장만 자른다. 표현은 고치지 않는다. 여기서 **역할**과 **목표**를 뽑는다.

작업이 여러 발화에 걸쳐 서서히 정해졌다면, 요구가 처음 확정된 발화를 최초 지시로 본다.

### 2) 중간 수정 지시

1차 결과 이후에 나온 교정 요구다. 판정 기준은 "이 말이 없었다면 결과가 달랐는가"다.

- 같은 취지가 반복되면 하나로 합친다.
- 서로 어긋나는 지시가 있으면 **나중 것을 채택**하고, 앞의 것은 3)으로 내린다.
- 순서 자체가 중요한 경우(A를 먼저 해야 B가 가능)에는 절차 번호를 그 순서로 고정한다.

### 3) 통하지 않은 지시

기대와 다른 결과가 나왔던 지점이다. 두 가지를 함께 적는다. 지시 원문, 그리고 무엇이 어긋났는지 한 줄.

이 칸이 배포본의 [제약]이 된다. 받는 사람이 같은 함정에 빠지는 것을 막는 자리라, 원인을 적어야 쓸모가 있다. "표가 이상하게 나옴"이 아니라 "열 개수를 지정하지 않아 5열로 나옴"처럼 적는다.

### 4) 합격 기준

최종 결과를 받아들인 이유다. 확인 가능한 것만 적는다.

- 적는다: 분량, 구조, 항목 수, 오류 없이 실행됨, 지정한 형식 준수
- 적지 않는다: 마음에 듦, 품질이 좋음, 자연스러움

로그에 "좋다", "이거면 됨" 같은 승인만 있고 이유가 없으면 추측하지 말고 사용자에게 기준을 묻는다.

### 5) 매번 바뀐 값

같은 작업을 다시 할 때 사람이 갈아 끼울 값이다. 판정 기준은 "이 값을 바꿔도 절차가 그대로인가"다. 그렇다면 변수, 아니면 고정값이다.

흔한 변수 후보: 주제, 대상 독자, 분량, 형식, 파일명, 개수, 기한, 어조.

## 2. 발화 귀속 구분

배포본 품질이 가장 크게 갈리는 지점이다. 로그에는 세 종류 발화가 섞여 있다.

| 출처 | 처리 |
| --- | --- |
| 사용자가 처음부터 요구한 것 | 요구 그대로 반영. 바꾸지 않는다 |
| 어시스턴트가 제안하고 사용자가 채택한 것 | 프롬프트에 고정값으로 박는다 |
| 어시스턴트가 제안했으나 사용자가 반응하지 않은 것 | 넣지 않는다 |

세 번째가 특히 새기 쉽다. 침묵은 동의가 아니다. 어시스턴트가 열 가지를 제안하고 사용자가 "좋아요"라고만 했다면, 사용자가 승인한 것은 **묶음 전체의 방향**이지 열 가지 각각이 아니다. 개별 항목을 사용자 요구인 것처럼 [제약]에 올리지 않는다.

판단이 어려우면 기록지에 `(제안 출처: 어시스턴트)`를 붙여 두고 사용자에게 확인한다.

## 3. 범용화 치환표

배포본은 어느 서비스에서나 돌아야 한다. 아래 표현이 남아 있으면 바꾼다.

| 로그에 있는 표현 | 배포본에서 |
| --- | --- |
| 파일 경로 (`/mnt/...`, `C:\...`) | "아래에 내용을 붙여넣는다" |
| "업로드한 파일을 읽고" | "아래 자료를 참고해" + 붙여넣기 자리 |
| 확장 기능·스킬 이름 호출 | 그 기능이 하던 절차를 문장으로 풀어 쓰기 |
| "검색해서 확인해" | "확인이 어려우면 불확실하다고 표시하라" |
| "코드를 실행해서" | "실행 결과를 가정하지 말고 코드만 제시하라" |
| "아까 그 문서", "위에서 만든 것" | 값을 프롬프트 안에 직접 적기 |
| 프로젝트 지침·계정 설정에 의존한 규칙 | 프롬프트 본문에 규칙으로 옮겨 적기 |
| 특정 모델 이름·버전 지정 | 삭제. 필요하면 능력 요건으로 서술 |
| 화면 UI 조작 안내("왼쪽 메뉴에서") | 삭제. 프롬프트는 텍스트로만 동작 |

마지막 항목을 덧붙여 설명하면, 배포본은 **입력창에 붙여넣는 텍스트**다. 도구 조작 안내가 섞이면 받는 사람이 프롬프트의 어디까지를 복사해야 하는지 헷갈린다. 조작 안내가 꼭 필요하면 프롬프트 밖 "사용 안내"에 적는다.

## 4. 자주 나오는 실수

- **요약해 버린다.** 로그를 압축한 설명문이 나온다. 배포본은 설명이 아니라 지시문이다. 문장은 명령형으로 쓴다.
- **절차가 너무 잘다.** 열다섯 단계짜리 절차는 지켜지지 않는다. 3~7단계로 묶는다.
- **제약이 금지 목록뿐이다.** "하지 마라"만 있으면 대체 행동이 없어 결과가 흔들린다. 짝을 지어 적는다.
- **변수를 본문에 예시로 박는다.** `{주제}` 자리에 실제 주제가 들어가 있으면 받는 사람이 지우지 않고 그대로 쓴다.
- **합격 기준이 주관적이다.** 검증 단계에서 통과 여부를 판정할 수 없게 된다.
- **로그에 없는 것을 채운다.** 그럴듯해 보여도 검증되지 않은 지시다. 비워 두고 사용자에게 묻는다.
