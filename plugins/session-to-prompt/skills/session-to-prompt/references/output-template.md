# 산출 .md 템플릿

## 파일명

`prompt-<작업슬러그>-v1.md`

슬러그는 소문자 영문과 하이픈으로 짓는다. 같은 작업을 고치면 `v2`, `v3`로 번호만 올린다. 이미 배포한 판은 지우지 않는다. 받는 사람이 가진 판과 내가 고친 판이 달라졌을 때 어느 쪽 이야기인지 구분해야 하기 때문이다.

## 전체 틀

아래 네 덩어리를 이 순서로 쓴다. 제목 수준까지 그대로 맞춘다.

```markdown
# (작업 이름) 프롬프트

## 사용 방법

1. 아래 프롬프트를 통째로 복사해 AI 서비스 입력창에 붙여넣는다.
2. `{ }` 표시가 있는 자리를 자기 상황에 맞는 값으로 바꾼다.
3. 결과가 나오면 문서 끝의 "확인 항목"으로 검사한다.

## 프롬프트

​```
[역할] 너는 (분야)를 다루는 (역할)이다.

[목표] (완성했을 때 손에 남는 결과물 한 문장)

[입력값]
- 항목1: {여기에 채우기}
- 항목2: {여기에 채우기}

[수행 절차]
1. (첫 단계)
2. (둘째 단계)
3. (셋째 단계)

[출력 형식]
- (분량, 구조, 표·목록 여부)

[제약]
- (하지 말 것 + 대신 할 것)
​```

## 채워 넣을 값

| 변수 | 설명 | 예시 |
| --- | --- | --- |
| {항목1} | (무엇을 넣는 자리인지) | (예시 값) |
| {항목2} | (무엇을 넣는 자리인지) | (예시 값) |

## 확인 항목

- [ ] (확인 가능한 기준 1)
- [ ] (확인 가능한 기준 2)
- [ ] (확인 가능한 기준 3)

## 잘 안 될 때

- (자주 생기는 어긋남): (어떻게 고쳐 말하면 되는지)
```

## 각 덩어리를 쓸 때

### 사용 방법

세 줄을 넘기지 않는다. 받는 사람이 여기서 막히면 프롬프트를 열어 보지도 않는다.

### 프롬프트

코드블록 하나에 통째로 넣는다. 중간에 설명을 끼워 넣어 블록을 쪼개지 않는다. 쪼개면 복사할 범위가 모호해져 일부만 붙여넣는 사고가 난다.

블록 안에는 마크다운 강조 표시를 쓰지 않는다. 입력창에 그대로 들어가는 글자이므로 `**` 같은 기호는 잡음이 된다.

### 채워 넣을 값

예시 열이 실제로는 가장 많이 읽히는 자리다. "주제를 적으세요" 같은 설명보다 채워진 예시 하나가 이해가 빠르다. 예시는 프롬프트 본문이 아니라 이 표에만 둔다.

### 확인 항목

체크박스로 적고, 하나하나가 눈으로 확인 가능해야 한다.

- 좋음: 표가 3열인가 / 분량이 A4 한 장 이내인가 / 코드에 주석이 있는가
- 나쁨: 내용이 충실한가 / 자연스러운가

### 잘 안 될 때

기록지의 "통하지 않은 지시"에서 나온다. 어긋난 증상과 교정 문장을 짝지어 적는다. 이 항목이 있으면 받는 사람이 질문 없이 스스로 고친다. 근거가 없으면 이 절은 통째로 생략한다.

## 여러 건을 한 번에 만들 때

작업 하나당 파일 하나다. 한 파일에 여러 프롬프트를 넣지 않는다. 받는 사람이 어디까지 복사해야 할지 알기 어렵고, 판올림도 따로 못 한다.

여러 건이면 폴더 하나에 모으고 목록 파일을 따로 둔다.

```
prompts/
  README.md              (작업 이름과 용도 한 줄씩)
  prompt-<작업A>-v1.md
  prompt-<작업B>-v1.md
```
