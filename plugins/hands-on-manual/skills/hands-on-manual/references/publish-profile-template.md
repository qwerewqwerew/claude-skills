# 발행 프로필 작성 서식

이 스킬은 매뉴얼을 **마크다운**으로 쓴다. 그 마크다운을 특정 사이트에 올리는 규칙은 사이트마다
다르므로 스킬 안에 담지 않고, 프로필 문서 하나를 읽어서 따른다.

## 어디에 두나

```
~/.claude/manual-profiles/<사이트이름>.md
```

`MANUAL_PROFILE_DIR` 환경변수로 폴더를 바꿀 수 있다. 스킬 폴더 안에 두지 않는 이유는 두 가지다 —
프로필은 사용자마다 다르고, 플러그인은 버전별 디렉터리에 설치돼 업데이트하면 안에 둔 파일이 지워진다.

파일 하나가 사이트 하나다. 여러 사이트에 올린다면 파일을 여러 개 둔다.

## 무엇을 적나

아래 6절을 채운다. **모르는 항목은 비워 두고 "확인 안 됨"이라고 적는다.** 추측해서 채우면
스킬이 그 추측을 사실로 믿고 마크업을 만든다.

### 1. 사이트 개요

무엇으로 운영되는지, 어떤 테마·플러그인이 마크업에 관여하는지. 확인한 방법과 날짜를 함께 적는다.
사이트 구성은 바뀌므로 언제 확인한 정보인지가 중요하다.

### 2. 마크다운을 받는 경로

원고를 어떤 방법으로 넣는지. 관리자 화면의 임포트 메뉴, API, CLI 중 무엇인지.
그 경로가 마크다운을 **변환기에 태우는지** 아니면 **HTML 그대로 받는지**를 분명히 적는다.
이 구분에 따라 원고에 무엇을 쓸지가 완전히 달라진다.

### 3. 콜아웃

이 스킬은 `> [!INFO]` 형식으로 쓴다. 사이트가 이 표기를 색 박스로 바꿔 주는지 적는다.

- 바꿔 준다면 → 지원하는 태그 목록과 별칭
- 안 바꿔 준다면 → 대신 넣을 HTML 마크업 전문

### 4. 코드 블록

펜스 코드 블록이 무엇으로 렌더되는지. 언어 지정이 어느 속성으로 들어가는지.
같은 값을 두 군데 이상에 써야 하는 구조라면 그 사실을 적는다(한 곳만 고치면 조용히 어긋난다).

파일명 표시와 접이식 감싸기를 변환기가 해 주는지도 적는다. 대개 해 주지 않는다.

### 5. 그 밖의 블록

표·목록·이미지·구분선·버튼·탭 등에서 **기본 마크다운으로 안 되는 것만** 적는다.
그대로 통하는 블록은 적을 필요가 없다.

### 6. 분류와 메타데이터

카테고리·태그를 어떤 필드로 넘기는지, 실제 슬러그 목록은 무엇인지.
없는 슬러그를 넘기면 어떻게 되는지(대개 조용히 미분류로 등록된다).

## 프로필과 무관하게 지켜지는 것

아래는 SKILL.md의 "발행 프로필" 섹션이 이미 강제하므로 프로필에 다시 적지 않아도 된다.

- H1 이중 규칙 — 로컬 마스터(H1 포함)와 업로드본(H1 제거) 두 벌로 나눈다
- 초안으로 먼저 등록해 변환 결과를 확인한 뒤 공개로 바꾼다
- 분류 슬러그가 사이트에 실제로 있는지 확인한다

## 주의

프로필에는 **서버 접속 정보·절대경로·자격증명을 적지 않는다.** 프로필은 사이트에 올릴 마크업이
무엇인지를 적는 문서다. 접속이 필요한 작업은 그때 사용자에게 받는다.
