# 설명서 문체 치환표 (hands-on-manual 정본)

실습 매뉴얼의 문체를 설명서(매뉴얼) 격의 글말로 통일하는 규칙이다. SKILL.md "문체 규칙" 섹션의 근거 문서이며, 아래 표가 금지/대체 표현의 **정본**이다.

쓰는 때는 두 번이다.

1. **본문을 쓰기 전** — 5절 "용어 고정표"를 먼저 잡는다.
2. **원고를 내보내기 전** — 1~4절 표의 금지 표현을 문서에서 하나씩 검색해 전부 걷어낸다.

전제는 그대로 둔다. 평어체(한다·이다)와 쉬운 말은 유지하고, 격만 설명서에 맞춘다. 어렵게 쓰라는 뜻이 아니다.

---

## 1. 입말·구어 지시어 → 글말

말할 때는 자연스러워도 문서에 적으면 지시 대상이 흐려지는 표현이다. 학습자는 소리로 듣지 않고 눈으로 읽으므로, 무엇을 가리키는지 글자만으로 분명해야 한다.

| 금지 표현 | 대체 표현 | 왜 |
| --- | --- | --- |
| 앞엣것 / 뒤엣것 | 첫 번째 경우 / 두 번째 경우 | 대상이 몇 줄 위에 있으면 "앞"이 어디인지 되짚어야 한다 |
| 두 갈래 / 세 갈래 | 아래 항목 / 두 가지 / 아래 두 가지 | "갈래"는 구어체이고 개수·범위가 모호하다 |
| 이런 것들 / 저런 경우 | 위 표의 항목 / 앞 절에서 만든 파일 | 지시 대상을 이름으로 부른다 |
| 얘 / 걔 / 이 녀석 | 이 파일 / 이 명령 / 이 설정 | 대상을 사물 이름으로 부른다 |
| ~하는 거다 / ~인 거다 | ~한다 / ~이다 | 구어 어미를 평서 종결로 바꾼다 |
| 좀 / 막 / 그냥 | (삭제) | 뜻을 더하지 않는 군더더기다 |

## 2. 속어·과장 → 중립 서술

기술 현상을 사람의 성격이나 감정으로 빗대면, 학습자는 그 현상이 실제로 무엇인지 알 수 없다.

| 금지 표현 | 대체 표현 |
| --- | --- |
| 멍청해진다 | 이전 맥락을 잃어 답변 품질이 떨어진다 |
| 뻗는다 / 죽는다 | 응답이 멈춘다 / 프로세스가 종료된다 |
| 터진다 | 오류가 발생한다 |
| 어마어마하게 / 엄청 | (수치로 적는다) 3배로 / 200MB까지 |
| 무조건 / 절대 | 항상 / 예외 없이 (근거를 한 줄 덧붙인다) |

## 3. 감정 판단어 → 중립 서술 + 이유

"곤란하다", "위험하다" 같은 말은 글쓴이의 감정만 전할 뿐, 무엇이 어떻게 잘못되는지는 알려 주지 않는다. **중립 서술로 바꾸고 그 뒤에 이유를 한 줄 붙인다.**

| 금지 표현 | 대체 표현 |
| --- | --- |
| 물려받으면 곤란하다 | 팀 전체에 공유되는 것은 바람직하지 않다 — 개인 설정이 다른 사람 작업에도 적용되기 때문이다 |
| 이러면 큰일 난다 | 이 경우 앞서 만든 파일을 덮어쓴다 |
| 아주 위험하다 | 되돌릴 수 없다 — 삭제한 파일은 휴지통을 거치지 않는다 |
| 답답하다 / 짜증난다 | 응답까지 30초가 걸린다 |

## 4. 의인화·모호한 기능 서술 → 조건·동작 정의문

도구는 호의를 베풀지 않는다. 기능 설명은 **언제(조건) + 무엇을(대상) + 어떻게 한다(동작)** 세 조각을 갖춘 정의문으로 적는다. 세 조각 중 하나라도 비면 학습자는 그 기능이 언제 작동하는지 스스로 짐작해야 한다.

| 금지 표현 | 대체 표현 | 빠진 조각 |
| --- | --- | --- |
| 자동으로 먼저 읽어 준다 | 세션을 시작할 때 가장 먼저 읽는 파일이다 | 언제(조건) |
| 알아서 정리해 준다 | 대화가 한도에 닿으면 앞부분을 요약해 남긴다 | 언제(조건) |
| 기억해 준다 / 잊어버린다 | 이 파일에 적은 내용은 다음 세션에서도 다시 읽는다 | 무엇을(대상) |
| 똑똑하게 골라 준다 | 확장자가 일치하는 파일만 목록에 넣는다 | 어떻게(동작) |
| 도와준다 | 명령을 대신 실행하고 결과를 화면에 출력한다 | 어떻게(동작) |

## 5. 용어 고정표 (본문을 쓰기 전에 만든다)

같은 기능을 자리마다 다른 말로 적으면, 초보 학습자는 같은 기능인지 다른 기능인지 판단하지 못한다. **한 기능에는 한 문장만 쓴다.**

본문을 쓰기 전에 그 문서가 다루는 기능·용어를 뽑아 정의문 한 줄씩을 미리 정한다. 이 표는 작성자 내부용이며 **산출 문서에는 넣지 않는다.**

작성 규칙은 세 가지다.

1. 정의문은 조건·동작 기준으로 적는다(4절).
2. 문서 전체에서 이 문장만 되풀이한다. 자리마다 표현을 바꾸지 않는다.
3. **짝을 이루는 개념은 같은 문형에 값만 바꿔 나란히 적는다.** 문형이 서로 다르면 두 개념의 차이가 어디인지 학습자가 직접 찾아내야 한다.

예시(Claude Code 계열 문서의 고정표):

| 용어 | 고정 정의문 |
| --- | --- |
| CLAUDE.md | 세션을 시작할 때 가장 먼저 읽는 파일이다 |
| `/compact` | 앞부분 대화를 요약해 컨텍스트 사용량을 줄인다 |
| `/clear` | 현재 세션을 초기화한다 |
| 오토메모리 | 반복되는 사용자 선호를 자동으로 저장하는 기능이다 |
| 스킬 | 현재 세션에서 실행되는 작업 단위다 |
| 서브 에이전트 | 독립된 컨텍스트에서 실행되는 작업 단위다 |

`/compact`와 `/clear`는 둘 다 "무엇을 어떻게 한다" 한 문형이고, 스킬과 서브 에이전트는 "~에서 실행되는 작업 단위다" 한 문형에 실행 위치만 다르다. 이렇게 짝을 맞추면 차이가 한 줄에서 드러난다.

## 6. 정의 우선 순서 (정의 → 원인·동작 → 비유)

새 개념은 다음 순서로만 꺼낸다.

1. **정의** — 그 말이 무엇인지 한 줄로 못 박는다.
2. **원인·동작** — 왜 그렇게 되는지, 어떻게 움직이는지 적는다.
3. **비유** — 필요하면 그 뒤에 붙인다.

비유어부터 꺼내면 학습자는 그 말이 무엇을 가리키는지 모른 채 설명을 읽는다.

- **나쁜 예**: "기억 그릇이 차면 앞부분이 밀려난다. 그래서 대화가 길어지면 앞 내용을 잊는다." — "기억 그릇"이 무엇인지 아직 정하지 않았다.
- **좋은 예**: "컨텍스트는 모델이 한 번에 들고 있는 대화 분량이다(정의). 이 분량이 다 차면 오래된 대화부터 밀려난다(원인·동작). 이 분량을 '기억 그릇'이라 부른다(비유)."

**비유는 문서당 하나**다. 중심 개념 하나에만 붙이고, 나머지 개념은 정의문으로 적는다. 개념마다 비유를 새로 붙이면 비유끼리 뒤엉켜 오히려 초보자를 헷갈리게 한다.

## 7. 스킬 내부 용어 → 학습자의 말

SKILL.md 지침의 용어는 작성자끼리의 약속이지 학습자의 언어가 아니다. 산출 문서에 그대로 새면 학습자는 낯선 은어를 만난다.

| 내부 용어 | 산출 문서 표현 |
| --- | --- |
| 손에 남는 / 손에 남기는 | 직접 만들어 본다 / 결과물이 남는다 |
| 손동작 단위로 쪼갠다 | 한 단계씩 따라 한다 |
| 실값 | 실제 값 / 아래 값 그대로 |
| 주제 묶음 / 작업 묶음 | (번호와 제목으로만 부른다) |
| 조립설명서 모드 | (문서에 쓰지 않는다) |

## 8. 독자 전제 일관성

오리엔테이션에서 정한 독자 수준을 문서 끝까지 바꾸지 않는다.

- **충돌 예**: 도입부는 "몇 번 써 봤는데"(경험자 전제)로 열고, 본문은 "처음 여는 자료"(초보 전제)로 적는 경우. 독자는 이 문서가 자기에게 맞는지 판단하지 못한다.
- **기본값**: 완전 초보. 그 도구를 처음 다루는 사람으로 잡는다.
- **경험자 전제를 쓰려면**: 오리엔테이션·본문·콜아웃을 모두 그 전제에 맞춘다. 한 곳이라도 초보 전제 문장이 남으면 충돌한다.

## 9. 내보내기 전 훑는 순서

1. 1~4절 표의 **금지 표현 칼럼을 문서에서 검색**한다. 한 건도 남지 않아야 한다.
2. 5절 **용어 고정표와 본문을 대조**한다. 같은 기능이 다른 문장으로 적힌 자리를 찾아 고정 문장으로 되돌린다.
3. 6절 **정의 우선 순서**를 어긴 자리를 찾는다. 비유어·원인 설명이 정의보다 앞선 곳이 있으면 순서를 바꾼다.
4. 7절 **내부 용어**가 산출문에 샜는지 검색한다.
5. 8절 **독자 전제**가 한 가지인지 도입부와 본문을 대조한다.
