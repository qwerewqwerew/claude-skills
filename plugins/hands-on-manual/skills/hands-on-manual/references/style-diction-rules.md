# 설명서 문체 치환표 (hands-on-manual 정본)

실습 매뉴얼의 문체를 설명서(매뉴얼) 격의 글말로 통일하는 규칙이다. SKILL.md "문체 규칙" 섹션의 근거 문서이며, 아래 표가 금지/대체 표현의 **정본**이다.

쓰는 때는 두 번이다.

1. **본문을 쓰기 전** — 5절 "용어 고정표"를 먼저 잡고, 13절 "모범 문단"을 읽어 산출 문서가 낼 목소리를 정한다.
2. **원고를 내보내기 전** — 1~4절과 9~10절 표의 금지 표현을 문서에서 하나씩 검색해 전부 걷어내고, 바꾼 문장은 전체를 다시 읽어 조사·호응을 맞춘 뒤(12절), 11절의 문장 규칙으로 한 번 더 훑는다.

전제는 그대로 둔다. 종결어미는 합니다체 평서형(합니다·입니다)으로 고정하고, 쉬운 말은 유지하며, 격만 설명서에 맞춘다. 어렵게 쓰라는 뜻이 아니다.

---

## 1. 입말·구어 지시어 → 글말

말할 때는 자연스러워도 문서에 적으면 지시 대상이 흐려지는 표현이다. 학습자는 소리로 듣지 않고 눈으로 읽으므로, 무엇을 가리키는지 글자만으로 분명해야 한다.

| 금지 표현 | 대체 표현 | 왜 |
| --- | --- | --- |
| 앞엣것 / 뒤엣것 | 첫 번째 경우 / 두 번째 경우 | 대상이 몇 줄 위에 있으면 "앞"이 어디인지 되짚어야 한다 |
| 두 갈래 / 세 갈래 | 아래 항목 / 두 가지 / 아래 두 가지 | "갈래"는 구어체이고 개수·범위가 모호하다 |
| 이런 것들 / 저런 경우 | 위 표의 항목 / 앞 절에서 만든 파일 | 지시 대상을 이름으로 부른다 |
| 얘 / 걔 / 이 녀석 | 이 파일 / 이 명령 / 이 설정 | 대상을 사물 이름으로 부른다 |
| ~하는 거다 / ~인 거다 / ~하는 거예요 | ~합니다 / ~입니다 | 구어 어미를 합니다체 평서 종결로 바꾼다 |
| 좀 / 막 / 그냥 | (삭제) | 뜻을 더하지 않는 군더더기다 |

## 2. 속어·과장·유행어 → 중립 서술

기술 현상을 사람의 성격이나 감정으로 빗대면, 학습자는 그 현상이 실제로 무엇인지 알 수 없다. 유행어는 몇 년 뒤 읽는 학습자에게 뜻이 닿지 않으므로 함께 금지한다.

| 금지 표현 | 대체 표현 |
| --- | --- |
| 멍청해집니다 | 이전 맥락을 잃어 답변 품질이 떨어집니다 |
| 뻗습니다 / 죽습니다 | 응답이 멈춥니다 / 프로세스가 종료됩니다 |
| 터집니다 | 오류가 발생합니다 |
| 어마어마하게 / 엄청 | (수치로 적는다) 3배로 / 200MB까지 |
| 무조건 / 절대 | 항상 / 예외 없이 (근거를 한 줄 덧붙인다) |
| 유행어(꿀팁·갓성비·찐 등) | (표준어로) 유용한 방법 / 값에 비해 성능이 좋습니다 / 실제 |

## 3. 감정 판단어 → 중립 서술 + 이유

"곤란합니다", "위험합니다" 같은 말은 글쓴이의 감정만 전할 뿐, 무엇이 어떻게 잘못되는지는 알려 주지 않는다. **중립 서술로 바꾸고 그 뒤에 이유를 한 줄 붙인다.**

| 금지 표현 | 대체 표현 |
| --- | --- |
| 물려받으면 곤란합니다 | 팀 전체에 공유되는 것은 바람직하지 않습니다 — 개인 설정이 다른 사람 작업에도 적용되기 때문입니다 |
| 이러면 큰일 납니다 | 이 경우 앞서 만든 파일을 덮어씁니다 |
| 아주 위험합니다 | 되돌릴 수 없습니다 — 삭제한 파일은 휴지통을 거치지 않습니다 |
| 답답합니다 / 짜증납니다 | 응답까지 30초가 걸립니다 |

## 4. 의인화·모호한 기능 서술 → 조건·동작 정의문

도구는 호의를 베풀지 않는다. 기능 설명은 **언제(조건) + 무엇을(대상) + 어떻게 한다(동작)** 세 조각을 갖춘 정의문으로 적는다. 세 조각 중 하나라도 비면 학습자는 그 기능이 언제 작동하는지 스스로 짐작해야 한다.

| 금지 표현 | 대체 표현 | 빠진 조각 |
| --- | --- | --- |
| 자동으로 먼저 읽어 줍니다 | 세션을 시작할 때 가장 먼저 읽는 파일입니다 | 언제(조건) |
| 알아서 정리해 줍니다 | 대화가 한도에 닿으면 앞부분을 요약해 남깁니다 | 언제(조건) |
| 기억해 줍니다 / 잊어버립니다 | 이 파일에 적은 내용은 다음 세션에서도 다시 읽습니다 | 무엇을(대상) |
| 똑똑하게 골라 줍니다 | 확장자가 일치하는 파일만 목록에 넣습니다 | 어떻게(동작) |
| 도와줍니다 | 명령을 대신 실행하고 결과를 화면에 출력합니다 | 어떻게(동작) |

## 5. 용어 고정표 (본문을 쓰기 전에 만든다)

같은 기능을 자리마다 다른 말로 적으면, 초보 학습자는 같은 기능인지 다른 기능인지 판단하지 못한다. **한 기능에는 한 문장만 쓴다.**

본문을 쓰기 전에 그 문서가 다루는 기능·용어를 뽑아 정의문 한 줄씩을 미리 정한다. 이 표는 작성자 내부용이며 **산출 문서에는 넣지 않는다.**

작성 규칙은 네 가지다.

1. 정의문은 조건·동작 기준으로 적는다(4절).
2. 문서 전체에서 이 문장만 되풀이한다. 자리마다 표현을 바꾸지 않는다.
3. **짝을 이루는 개념은 같은 문형에 값만 바꿔 나란히 적는다.** 문형이 서로 다르면 두 개념의 차이가 어디인지 학습자가 직접 찾아내야 한다.
4. **고정하는 것은 용어와 서술 골격이다.** 문장 속 자리에 맞춰 조사·어미는 자연스럽게 활용한다. 고정문을 통째로 끼워 넣어 앞뒤와 호응이 어긋나면 비문이 된다. 예: 고정문이 "현재 세션을 초기화합니다"라면, 문장 속에서는 "세션 초기화 명령으로 현재 세션을 초기화한 뒤"처럼 어미를 바꿔 잇는다.

예시(대화형 AI 도구를 다루는 문서의 고정표):

| 용어 | 고정 정의문 |
| --- | --- |
| 지침 파일 | 세션을 시작할 때 가장 먼저 읽는 파일입니다 |
| 대화 압축 | 앞부분 대화를 요약해 컨텍스트 사용량을 줄입니다 |
| 세션 초기화 | 현재 세션을 초기화합니다 |
| 오토메모리 | 반복되는 사용자 선호를 자동으로 저장하는 기능입니다 |
| 스킬 | 현재 세션에서 실행되는 작업 단위입니다 |
| 서브 에이전트 | 독립된 컨텍스트에서 실행되는 작업 단위입니다 |

대화 압축과 세션 초기화는 둘 다 "무엇을 어떻게 합니다" 한 문형이고, 스킬과 서브 에이전트는 "~에서 실행되는 작업 단위입니다" 한 문형에 실행 위치만 다르다. 이렇게 짝을 맞추면 차이가 한 줄에서 드러난다.

## 6. 정의 우선 순서 (정의 → 원인·동작 → 비유)

새 개념은 다음 순서로만 꺼낸다.

1. **정의** — 그 말이 무엇인지 한 줄로 못 박는다.
2. **원인·동작** — 왜 그렇게 되는지, 어떻게 움직이는지 적는다.
3. **비유** — 필요하면 그 뒤에 붙인다.

비유어부터 꺼내면 학습자는 그 말이 무엇을 가리키는지 모른 채 설명을 읽는다.

- **나쁜 예**: "기억 그릇이 차면 앞부분이 밀려납니다. 그래서 대화가 길어지면 앞 내용을 잊습니다." — "기억 그릇"이 무엇인지 아직 정하지 않았다.
- **좋은 예**: "컨텍스트는 모델이 한 번에 들고 있는 대화 분량입니다(정의). 이 분량이 다 차면 오래된 대화부터 밀려납니다(원인·동작). 이 분량을 '기억 그릇'이라 부릅니다(비유)."

**비유는 문서당 하나**다. 중심 개념 하나에만 붙이고, 나머지 개념은 정의문으로 적는다. 개념마다 비유를 새로 붙이면 비유끼리 뒤엉켜 오히려 초보자를 헷갈리게 한다.

## 7. 스킬 내부 용어 → 학습자의 말

SKILL.md 지침의 용어는 작성자끼리의 약속이지 학습자의 언어가 아니다. 산출 문서에 그대로 새면 학습자는 낯선 은어를 만난다.

| 내부 용어 | 산출 문서 표현 |
| --- | --- |
| 손에 남는 / 손에 남기는 | 직접 만들어 봅니다 / 결과물이 남습니다 |
| 손동작 단위로 쪼갠다 | 한 단계씩 따라 합니다 |
| 실값 | 실제 값 / 아래 값 그대로 |
| 주제 묶음 / 작업 묶음 | (번호와 제목으로만 부른다) |
| 조립설명서 모드 | (문서에 쓰지 않는다) |

## 8. 독자 전제 일관성

오리엔테이션에서 정한 독자 수준을 문서 끝까지 바꾸지 않는다.

- **충돌 예**: 도입부는 "몇 번 써 봤는데"(경험자 전제)로 열고, 본문은 "처음 여는 자료"(초보 전제)로 적는 경우. 독자는 이 문서가 자기에게 맞는지 판단하지 못한다.
- **기본값**: 완전 초보. 그 도구를 처음 다루는 사람으로 잡는다.
- **경험자 전제를 쓰려면**: 오리엔테이션·본문·콜아웃을 모두 그 전제에 맞춘다. 한 곳이라도 초보 전제 문장이 남으면 충돌한다.

## 9. 이중부정·번역투 → 긍정 직서

이중부정은 읽는 사람이 부정을 두 번 뒤집어야 뜻이 잡힌다. 번역투는 우리말 어순·조사에 맞지 않아 읽는 속도를 늦춘다. 둘 다 긍정 직서로 바꾼다.

| 금지 표현 | 대체 표현 |
| --- | --- |
| ~하지 않을 수 없습니다 | ~해야 합니다 |
| ~이 아니라고 할 수 없습니다 | ~입니다 |
| ~하지 않으면 안 됩니다 | ~해야 합니다 |
| 없지 않습니다 | 있습니다 |
| ~에 있어서 | ~에서 / ~할 때 |
| ~적인 측면 | ~인 면 / ~쪽 |
| ~을 통해 | ~로 / ~을 써서 |
| ~에 대하여 | ~을 / ~에 관해 |
| ~함으로써 | ~해서 / ~하면 |
| ~로 인해 / ~에 의해 | ~ 때문에 / ~해서 |
| ~을 가지고 있습니다 / ~를 갖습니다 | ~이 있습니다 |
| ~하는 것이 가능합니다 | ~할 수 있습니다 |
| 존재합니다 | 있습니다 |
| 및 | 와 / 과 / 그리고 |
| 만약 ~한다면 | ~하면 |
| 그것은 / 이것은 (대명사 남용) | (앞 명사를 다시 쓰거나 생략한다) |
| 파일들 / 값들 (복수 "~들" 남용) | 파일 / 값 (여럿임을 밝혀야 하면 "여러 파일") |
| ~하는 것이 필요합니다 | ~해야 합니다 |

**이 표는 낱말 갈아 끼우기 표가 아니다.** 표현을 바꾼 뒤에는 문장 전체를 다시 읽어 조사와 호응(주어-서술어, 목적어-서술어)이 맞는지 확인한다. 단어만 바꿔 어색해지면 그 문장을 통째로 다시 쓴다.

## 10. 어림말 → 정확한 값과 단위

"꽤", "여러 번" 같은 어림말은 사람마다 다르게 읽는다. 학습자가 기다릴지 다시 시도할지 판단하려면 수치가 필요하다. 값이 상황마다 달라 하나로 못 박을 수 없으면 범위로 적는다.

| 금지 표현 | 대체 표현 |
| --- | --- |
| 꽤 오래 / 한참 | 약 10분 |
| 잠시 후 / 곧 | 약 5초 뒤 |
| 여러 번 / 몇 번 | 3회 |
| 충분히 큰 | 200MB 이상 |
| 조금만 기다리면 | 30초~2분 안에 |
| 대부분 / 거의 다 | 10개 중 9개 / 약 90% |

## 11. 읽기 쉬운 문장 규칙

문장·문단·단어 수준에서 지키는 규칙이다. SKILL.md의 "문체 규칙"·"초보자가 따라오게 쓰는 법"과 같은 내용이며, 여기가 정본이다.

1. **결론을 먼저 쓴다.** 문서는 첫 단락에서, 문단은 첫 문장에서 무엇을 말하는지 밝힌다. 결론이 뒤에 있으면 앞으로 끌어올린다.
2. **한 문장에는 한 가지 생각만 담는다.** 50자 안팎을 눈대중 기준으로 삼되, 글자 수를 맞추려고 조사·어미·연결어를 잘라 내지 않는다. 온전한 문장이 짧은 문장보다 먼저다. 실값(URL·명령어·경로)이 들어가 길어지는 문장은 예외다.
3. **초등학교 6학년이 읽어도 이해할 수 있는 단어를 쓴다.** 이 기준을 넘는 단어는 더 쉬운 말로 바꾼다.
4. **전문용어는 처음 나오는 자리에서 괄호로 한 줄 풀이를 붙인다.** 예: 배포(만든 것을 인터넷에 올려 누구나 볼 수 있게 하는 일). 두 번째부터는 용어만 쓴다.
5. **추상적인 설명 뒤에는 일상 속 예시를 하나 붙인다.** 예시는 자리마다 붙여도 된다. 단 비유(개념을 다른 이름으로 부르는 것)는 6절대로 문서당 하나만 쓴다.
6. **주어는 동작 주체가 헷갈릴 자리에서만 밝힌다.** 손동작 지시문의 주어(학습자)는 늘 생략한다 — "Chrome을 엽니다"이지 "학습자는 Chrome을 엽니다"가 아니다. 도구가 하는 일을 처음 말하거나 앞 문장과 주체가 바뀌는 자리에서만 "브라우저가 ~합니다"처럼 주어를 적는다. 우리말은 주어를 생략하는 언어라, 문장마다 주어를 붙이면 번역투가 된다.
7. **한 문단은 3~4문장을 넘기지 않는다.** 항목이 3개 이상이면 줄글로 잇지 말고 번호 목록으로 바꾼다.
8. **숫자는 어림말 대신 정확한 값과 단위로 쓴다**(10절).
9. **다 쓴 뒤 스스로 점검한다.** "독자가 이 글만 읽고 무엇을 알게 되는가"를 한 줄로 답해 보고, 그 목표와 무관한 문장은 지운다. 점검 결과는 산출 문서·채팅에 출력하지 않는다.

## 12. 비문·과축약 점검 (문장 성분 호응)

번역투를 걷어내고 문장을 짧게 나누는 과정에서 새로 생기는 오류를 잡는 절이다. 표현을 고친 문장일수록 호응이 어긋나기 쉬우므로, 고친 자리마다 아래 다섯 가지를 확인한다.

1. **호응**: 주어와 서술어, 목적어와 서술어가 맞물리는지 확인한다. "이 기능의 장점은 시간을 줄입니다"는 주어("장점은")와 서술어("줄입니다")가 어긋난 비문이다 — "이 기능의 장점은 시간을 줄여 준다는 것입니다" 또는 "이 기능을 쓰면 시간이 줄어듭니다"로 고친다.
2. **조사·어미를 잘라 낸 전보문 금지**: 문장을 줄이려고 조사와 서술어를 지우면 명사만 남은 전보문이 된다. "폴더 생성 후 파일 이동 진행"이 아니라 "폴더를 만든 다음 파일을 옮깁니다"로 적는다. 글자 수 규칙(50자 안팎·150자 한 행)은 조사·어미를 지키는 온전한 문장 안에서만 적용한다.
3. **나열의 대등성**: "~하고, ~하며"로 이을 때는 이어지는 성분의 층위를 맞춘다. "버튼을 누르고, 저장이 완료"처럼 동사와 명사를 섞어 잇지 않는다 — "버튼을 누르고, 저장을 확인합니다"로 맞춘다.
4. **태(능동/자동·피동)**: 학습자가 하는 동작은 능동으로("버튼을 클릭합니다"), 도구·화면이 일으키는 결과는 자연스러운 자동사·피동으로 적는다("창이 열립니다", "파일이 저장됩니다"). 결과 문장까지 억지로 능동으로 바꾸면 주어를 억지로 붙이게 되고 번역투가 된다. 금지하는 것은 이중피동("되어집니다", "보여집니다")이다.
5. **시제**: 일반 동작·규칙은 현재형("저장하면 파일이 남습니다"), 손동작의 결과로 이미 일어난 일은 과거형("프로젝트 폴더가 만들어졌습니다")으로 적는다. 군더더기 "~었"은 뜻이 같을 때만 뺀다 — 시제를 바꿔 가면서까지 지우면 사실과 어긋난다.

## 13. 모범 문단 (산출 문서의 목소리)

산출 문서가 낼 목소리의 본보기다. 본문을 쓰기 전에 한 번 읽고 이 목소리로 쓴다. SKILL.md 지침의 압축 문체("박는다", "실값", 가운뎃점 명사 나열)는 작성자용 속기이므로 산출 문서에 흉내 내지 않는다.

**나쁜 예** (번역투·비문·전보문이 섞인 문단):

> 프로젝트 생성을 통해 작업 환경 구축이 가능합니다. 학습자는 [New Project] 버튼 클릭 후 이름 입력 진행합니다. 그것은 이후 모든 파일들이 저장되어지는 공간을 갖습니다.

무엇이 잘못됐는지: "~을 통해 ~이 가능합니다"(번역투), "학습자는"(불필요한 주어), "클릭 후 이름 입력 진행합니다"(조사·서술어를 지운 전보문), "그것은"(대명사 남용), "파일들"(복수 남용), "저장되어지는"(이중피동), "공간을 갖습니다"(번역투).

**좋은 예** (같은 내용을 이 스킬의 목소리로 쓴 문단):

> 프로젝트는 작업 파일을 한곳에 모아 두는 공간입니다. 먼저 프로젝트를 만들어 작업 환경을 준비합니다.
>
> 1. 화면 우상단의 [New Project] 버튼을 클릭합니다.
> 2. 이름 입력란에 `my-first-site`를 입력합니다.
> 3. `Enter` 키를 누릅니다.
>
> 왼쪽 사이드바에 `my-first-site` 폴더가 나타납니다. 앞으로 만드는 파일은 모두 이 폴더 안에 저장됩니다.

무엇이 좋은지: 정의문으로 열고(정의 우선), 손동작은 주어 없이 능동으로 적었으며, 입력값과 위치를 그대로 적었다. 결과는 "나타납니다·저장됩니다"처럼 자연스러운 자동사·피동으로 서술했다. 문장마다 조사와 서술어가 온전하다.

## 14. 내보내기 전 훑는 순서

1. 1~4절과 9~10절 표의 **금지 표현 칼럼을 문서에서 검색**한다. 한 건도 남지 않아야 한다. 표현을 바꾼 문장은 전체를 다시 읽어 조사·호응을 맞춘다.
2. 5절 **용어 고정표와 본문을 대조**한다. 같은 기능이 다른 문장으로 적힌 자리를 찾아 고정 문장으로 되돌리되, 조사·어미는 문장 자리에 맞게 활용한다.
3. 6절 **정의 우선 순서**를 어긴 자리를 찾는다. 비유어·원인 설명이 정의보다 앞선 곳이 있으면 순서를 바꾼다.
4. 7절 **내부 용어**가 산출문에 샜는지 검색한다.
5. 8절 **독자 전제**가 한 가지인지 도입부와 본문을 대조한다.
6. 11절 **읽기 쉬운 문장 규칙**으로 훑는다 — 두 생각이 든 긴 문장, 3~4문장을 넘는 문단, 풀이 없는 전문용어, 예시 없는 추상 설명을 찾아 고친다.
7. 12절 **비문·과축약 점검**으로 훑는다 — 호응이 어긋난 문장, 전보문, 억지 능동, 이중피동, 시제가 어긋난 문장을 찾아 고친다.
8. 15절 **상황 종속 표기**를 검색한다. 표의 금지 표현 칼럼과 함께 `차시`·`교시`·`분`·`시`·`조`·`강의실`·`STEP`을 문서에서 찾아, 남은 자리를 대체 표현으로 바꾼다.
9. 마지막으로 문서를 처음부터 **소리 내어 읽듯** 훑는다. 눈이 걸리는 문장은 13절 모범 문단의 목소리에 맞춰 다시 쓴다.

## 15. 상황 종속 표기 → 상황 중립 표현

같은 문서를 다른 기수·다른 기관에서, 혼자, 몇 달 뒤에 여는 사람이 있다. 한 번의 운영 상황(시간·장소·인원)에 묶인 표기는 그 상황 밖의 독자에게는 걸러 내며 읽어야 할 군더더기가 된다. SKILL.md 핵심 원칙 11이 정본이고, 여기는 자주 나오는 표현의 치환표다.

| 금지 표현 | 대체 표현 |
| --- | --- |
