# stitch-ppt-54: Google Stitch로 만드는 5:4 한국어 피치덱

이 스킬은 Google Stitch로 "Business Presentation | Pitch Deck" 피그마 템플릿 스타일의
한국어 발표자료를 만드는 작업을 3단계로 안내한다. 각 단계는 독립적으로 쓸 수 있다.
사용자가 이미 구성안을 갖고 있으면 2단계부터, 이미지를 갖고 왔으면 3단계부터 시작한다.

2단계의 기본 동작은 **Stitch 캔버스에 직접 디자인을 생성**하는 것이다(Stitch MCP
도구 사용). 도구가 없거나 권한이 막히면 프롬프트를 채팅에 출력하지 말고 md 문서로
저장해 전달한다. 어느 경우든 프롬프트 전문을 채팅창에 나열하지 않는다.

스타일의 원본은 실제 피그마 파일에서 추출한 값이다. 색상·폰트·레이아웃 수치는
`references/style-guide.md`에 있고, 프롬프트에 붙여 넣을 문구는
`references/prompt-templates.md`에 있다. 두 파일을 반드시 읽고 나서 프롬프트를 생성한다.

## 시작 전에 확인할 것

사용자에게 다음이 빠져 있으면 먼저 묻는다. 이미 대화에 있으면 다시 묻지 않는다.

1. 발표 주제와 목적(투자 유치, 회사 소개, 제품 소개, 수업 자료 등)
2. 슬라이드 수(모르면 10장 내외를 제안: 표지 1 + 섹션 3 + 본문 5 + 마무리 1)
3. 각 슬라이드에 들어갈 실제 내용(없으면 주제를 바탕으로 초안을 만들어 확인받는다)

## 1단계 — 한국어 슬라이드 구성안

발표 개요를 받아 슬라이드별 구성안을 표로 만든다. 각 줄에 다음을 적는다.

| 번호 | 슬라이드 유형 | 제목(한국어) | 본문 요점(한국어) | 시각 요소 |

슬라이드 유형은 반드시 `references/style-guide.md`의 7가지 원형(cover, divider,
card-grid, split-panel, photo-highlight, logo-grid, closing) 중에서 고른다.
템플릿의 흐름을 따르는 것이 자연스럽다: 다크 표지 → 질문형 섹션 디바이더 →
본문(카드/패널/사진) 반복 → 오렌지 마무리.

구성안을 사용자에게 보여주고 확인을 받은 뒤 2단계로 넘어간다.

## 2단계 — Stitch 캔버스에 직접 디자인 생성

`references/prompt-templates.md`를 읽고 슬라이드마다 영문 프롬프트를 하나씩 만든다.
프롬프트 작성 규칙은 다음과 같다.

- 프롬프트는 영문으로 쓴다. Stitch는 영문 프롬프트에서 가장 안정적으로 동작한다.
- 슬라이드에 표시될 한국어 텍스트는 프롬프트 안에 따옴표로 그대로 넣는다.
  예: heading text "인공지능 교육의 미래". Stitch가 한국어를 렌더링하지 못하고
  깨뜨리는 경우가 있으므로, 결과가 깨지면 같은 프롬프트를 영문 텍스트로 다시 생성한 뒤
  3단계에서 텍스트를 교체하는 폴백을 안내한다.
- 모든 프롬프트는 공통 스타일 블록(STYLE BLOCK)으로 시작한다. 이 블록이 슬라이드 간
  일관성을 만든다. 임의로 색상이나 폰트를 바꾸지 않는다.
- **완성된 프롬프트는 줄바꿈 없는 한 문단으로 만든다.** STYLE BLOCK과 유형 블록을
  이어 붙일 때 중간의 줄바꿈·빈 줄을 전부 공백 하나로 바꿔 문장을 연결한다.
  사용자가 전체를 한 번에 복사해 Stitch 입력창에 그대로 붙여넣을 수 있어야 한다.

**공통 규칙: 완성된 프롬프트 전문을 채팅창에 나열하지 않는다.** 직접 생성에
성공하면 도구에만 넘기고, 막히면 아래 2-2처럼 문서 파일로 저장한다. 채팅에는
진행 상황과 결과 요약만 짧게 적는다.

### 2-1. 직접 생성 (기본 경로)

사용 가능한 도구 목록에 Stitch 도구가 있으면(공식 Stitch MCP: stitch.googleapis.com,
또는 stitch-mcp / stitch-mcp-auto 같은 프록시 서버의 도구), 프롬프트를 사용자에게
넘기지 말고 그 도구로 Stitch 캔버스에 직접 화면을 생성한다.

1. 프로젝트를 하나 만든다(Web/데스크톱 기준, 5:4 1280×1024). 사용자가 기존 프로젝트를
   지정하면 그 프로젝트를 쓴다.
2. DESIGN.md 전문(`references/prompt-templates.md`에 있음)을 프로젝트에 등록하는
   도구가 있으면 먼저 등록한다. 없으면 각 프롬프트의 STYLE BLOCK으로 대신한다.
3. 1번 슬라이드부터 순서대로, **같은 프로젝트 안에서** 화면을 하나씩 생성한다
   (한 프롬프트 = 한 화면). 슬라이드마다 새 프로젝트를 만들면 스타일 기억이
   초기화되므로 절대 금지.
4. 화면이 하나 생성될 때마다 "몇 번 슬라이드 완료" 정도로만 짧게 보고한다.
   미리보기 링크나 이미지가 도구 결과로 오면 함께 보여준다.
5. 수정 요청이 오면 해당 화면에만 짧은 수정 지시를 보낸다. 전체 재생성은 하지 않는다.
6. 전부 생성되면 이미지 내보내기 방법을 안내하고 3단계로 넘어간다. 도구가 화면
   이미지를 직접 내려받을 수 있으면 받아서 바로 3단계 조립에 쓴다.

### 2-2. 권한이 막힌 경우 (폴백 — 프롬프트를 문서로 저장)

다음 중 하나라도 해당하면 "권한 막힘"으로 판단한다.

- 도구 목록에 Stitch 도구가 아예 없다
- 도구 호출이 인증·권한 오류로 실패한다(401/403, OAuth 미완료, Stitch API 미활성화 등)
- 사용자가 도구 실행 허용을 거부한다
- 사용량(quota) 초과로 생성이 거부된다

이때 **프롬프트를 채팅창에 바로 뱉지 말고**, 아래 구성의 md 문서 한 개로 저장해
파일로 전달한다. 파일명 예: `stitch-프롬프트.md`. 저장 위치는 환경에 맞춘다
(claude.ai는 /mnt/user-data/outputs에 저장 후 present_files로 전달,
Claude Code는 현재 작업 폴더).

문서 구성(위에서 아래 순서):

1. Stitch 수동 조작 순서 요약 — `references/stitch-guide.md`를 읽고 앞부분에 요약
2. DESIGN.md 전문 — Stitch 프로젝트 설정에 등록하도록 안내
3. 슬라이드 번호별 프롬프트 전문 — 슬라이드마다 "복사해서 붙여넣기" 할 수 있게
   코드 블록 하나씩. 코드 블록 안의 프롬프트는 줄바꿈 없는 한 문단이어야 한다

채팅창에는 직접 생성이 막힌 이유와 "프롬프트를 문서로 저장했다"는 안내만
한두 문장으로 남긴다. 문서 내용을 채팅에 다시 복사하지 않는다.

## 3단계 — Stitch 결과 이미지를 5:4 pptx로 조립

사용자가 Stitch에서 내보낸 슬라이드 이미지(PNG/JPG)를 업로드하면:

1. 파일명을 기준으로 슬라이드 순서를 정한다. 순서가 애매하면 사용자에게 확인한다.
2. `scripts/assemble_pptx.py`를 실행해 5:4(12192000×9753600 EMU, 즉 13.333×10.667인치)
   pptx를 만든다. 이미지는 슬라이드에 꽉 차게 배치되고, 비율이 다르면 여백 없이
   중앙 크롭된다.

```bash
pip install python-pptx --break-system-packages  # 없을 때만
python scripts/assemble_pptx.py <이미지폴더> -o 발표자료.pptx
python scripts/assemble_pptx.py <이미지폴더> -o 발표자료.pptx --notes notes.txt
```

3. 발표자 노트가 필요하면 1단계 구성안의 본문 요점으로 `notes.txt`를 만들어
   (슬라이드마다 `---` 구분) `--notes`로 넘긴다.
4. 완성된 pptx를 사용자에게 전달한다. 한국어가 깨진 슬라이드가 있으면,
   해당 슬라이드만 이미지 위에 pptx 텍스트 상자를 얹어 교체하는 방법을 제안한다
   (이때는 pptx 스킬의 편집 방법을 따른다).

## 자주 생기는 문제

- Stitch가 5:4가 아니라 세로 화면을 만든다 → 프롬프트 맨 앞의 화면비 지시가
  빠졌는지 확인한다. Web 모드인지도 확인한다(App 모드는 모바일 비율로 나온다).
- 슬라이드마다 색이 조금씩 다르다 → DESIGN.md를 프로젝트에 등록했는지 확인하고,
  같은 프로젝트 안에서 화면을 추가로 생성하게 안내한다(새 프로젝트를 만들면 스타일이 초기화된다).
- 한국어 글꼴이 명조체나 이상한 폰트로 나온다 → 프롬프트에 "Noto Sans KR" 지정이
  있는지 확인한다.
- 직접 생성이 도중에 실패한다 → 인증 만료나 사용량 초과일 수 있다. 같은 호출을
  한 번만 재시도하고, 또 실패하면 권한 막힘으로 판단해 2-2 폴백(문서 저장)으로
  전환한다. 이미 생성된 화면은 그대로 두고 남은 슬라이드 프롬프트만 문서에 담는다.
