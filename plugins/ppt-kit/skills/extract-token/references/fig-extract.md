# 소스 파일(.fig / .deck)에서 디자인 토큰 뽑기

사용자가 Figma 로컬 사본을 주면 거기서 색·타이포·라운드를 뽑아 테마 파일을 만든다.
슬라이드 레이아웃(원형 9종)은 소스에서 가져오지 않는다 — 소스가 발표자료라는
보장이 없으므로 `kiwik-card.md` 골격을 쓰고 **스타일만 교체**한다.

## 0. 먼저 알아 둘 것

- `.fig` = Figma Design, `.deck` = Figma Slides의 로컬 사본이다.
  (Figma 메뉴 → File → Save local copy)
- 두 포맷 모두 **Figma 비공개 형식이고 공개 스펙이 없다.** Figma 공식 문서도
  "형식이 바뀔 수 있고 서드파티 도구가 못 읽을 수 있다"고 적고 있다.
  즉 이 경로는 **공식 지원이 아니다.** 어느 날 갑자기 깨질 수 있고, 그때는
  아래 "포맷이 바뀌었을 때"를 따른다.
- 안정성이 중요하면 Figma REST API(파일 링크 + 액세스 토큰)가 공식 경로다.
  다만 파일을 직접 주고받는 방식은 아니다.

## 1. 실행

```bash
SKILL="${CLAUDE_PLUGIN_ROOT}/skills/extract-token"
[ -d "$SKILL/scripts/node_modules" ] || npm ci --prefix "$SKILL/scripts"
node "$SKILL/scripts/fig_decode.mjs" <파일.fig|.deck> -o message.json
python "$SKILL/scripts/fig_tokens.py" message.json -o tokens.json --theme <테마id>
```

- `fig_decode.mjs` — ZIP을 열어 `canvas.fig`(kiwi 바이너리)를 노드 트리 JSON으로 바꾼다.
- `fig_tokens.py` — 노드 트리에서 토큰을 뽑고 `~/.claude/ppt-themes/<테마id>.md`를 만든다.
  스킬 폴더 밖에 쓰는 이유는 SKILL.md 5단계에 있다. `PPT_THEME_DIR`로 위치를 바꿀 수 있다.
- `--theme`를 생략하면 토큰만 출력한다. 값을 먼저 확인하고 싶을 때 쓴다.

## 2. 파일 구조 (2026-07 확인)

```
파일.fig  (ZIP 컨테이너)
├── canvas.fig     'fig-kiwi' 매직 + version + [길이][청크] × 2
│                  청크0 = kiwi 스키마 (deflate 또는 비압축)
│                  청크1 = 노드 데이터 (zstd 또는 deflate)
├── meta.json      파일 이름, 썸네일 크기
├── thumbnail.png
└── images/…       원본 이미지 (해시 파일명)
```

압축 방식이 청크마다 다르고 버전에 따라 바뀐다. 디코더는 zstd → deflate → 원본
순으로 시도하므로 대개 그대로 통과한다.

## 3. 추출 규칙 — 이름이 있으면 이름을 믿는다

소스가 디자인 시스템 파일이면 토큰이 이름표와 함께 정리돼 있다. 그럴 때는
추정하지 않고 이름-값 쌍을 그대로 쓴다.

| 순위 | 근거 | 예 |
|---|---|---|
| 1 | 라벨 + 색 견본이 한 셀에 있는 프레임 | `color/bg/brand` → #3F63F4 |
| 2 | Figma 변수(VARIABLE)의 색상값 | `gray/500` → #71717A |
| 3 | 사용 빈도 추정 | 채도×명도×빈도 최고 색 → Primary |

시맨틱 이름 → 스킬 슬롯 매핑은 다음과 같다. 앞의 후보가 먼저 잡힌다.

| 슬롯 | 찾는 이름 |
|---|---|
| Primary | `color/bg/brand`, `color/text/brand`, `color/border/brand` |
| Background | `color/bg/base`, `color/bg/subtle` |
| Surface | `color/bg/surface`, `color/bg/subtle` |
| TextStrong | `color/text/primary` |
| TextBody | `color/text/secondary`, `color/text/muted` |
| PrimaryLite | `color/bg/brand-tint` |
| Contrast | 이름표 중 가장 어두운 색 (다크 표지 배경) |

`Contrast`가 `TextStrong`과 같은 값이면 표지에서 글자가 배경에 묻히므로,
다음으로 어두운 색으로 밀거나 자동으로 더 어둡게 보정한다.

타이포는 `Type/Display/Hero`, `Type/Body/Default` 처럼 이름 붙은 견본 프레임이
있으면 거기서 두께·자간·행간을 읽고, 없으면 최빈값을 쓴다.

## 3.5. 소스가 이미 발표자료 프레임일 때 — 위계·간격 실측

소스에 16:9 프레임이 여러 장 들어 있으면 크기 체계를 추정할 필요가 없다. 그 프레임의
TEXT 노드를 전부 읽어 **역할별 크기·두께·색을 그대로 표로 만든다.** `fig_tokens.py`는
색만 집계하므로 이 부분은 직접 한다. 절차는 이렇다.

1. 최상위 FRAME(부모가 CANVAS)의 `size`로 **소스 폭**을 확인한다. 1280 환산 배율은
   `1280 / 소스폭`이다(1920이면 ×0.667).
2. 각 TEXT 노드에서 `fontSize` / `fontName.style` / `lineHeight` / `letterSpacing` /
   `styleIdForFill`(이름 붙은 색 스타일)을 뽑아 프레임별로 정렬한다.
   같은 크기가 여러 프레임에 반복되면 그게 한 계층이다.
3. 간격은 `transform`의 `m02`/`m12`를 부모까지 누적해 **프레임 기준 절대 좌표**로 바꾼 뒤,
   위에서 아래로 정렬해 요소 사이 거리를 잰다. 여기서 상하좌우 여백, 라벨→헤드라인,
   헤드라인→콘텐츠, 열 거터, 행 피치가 나온다.
4. `stackMode`가 있는 프레임은 `stackSpacing` / `stackHorizontalPadding` /
   `stackVerticalPadding`을 그대로 쓴다. 없으면 3번의 실측값을 쓴다.
5. 여러 프레임에서 반복되는 최소 간격이 **기본 단위**다. 나머지 간격이 대체로
   그 배수인지 확인하고, 맞으면 배수로 정리해 적는다.

**렌더 이미지를 눈으로 보고 짐작한 값은 쓰지 않는다.** 실제로 kiwik 테마 초판은
상단 라벨을 "자간 넓게"로 적었는데, 노드를 재 보니 자간이 0이었다. 눈으로 본 인상과
파일 값이 다르면 파일 값을 쓴다.

## 4. 고정 규칙 (소스보다 우선한다)

- **한글 폰트는 항상 `Noto Sans KR`.** 소스가 다른 폰트를 써도 바꾸지 않는다.
  라틴 폰트만 소스 값을 따른다.
- **두께·자간·행간은 소스를 따르되, 행간은 1.4가 하한이다.** 웹 기준 행간(1.1~1.2)을
  슬라이드에 그대로 쓰면 좁아서 읽기 어렵다. 하한을 올린 경우 테마 파일 머리말에
  `소스 1.14 → 적용 1.4`처럼 남는다.
- **글자 크기는 소스가 아니라 슬라이드 스케일을 쓴다.** 소스가 웹이면 본문 17px
  같은 값이 1280×720 화면에서 너무 작다. 골격 테마의 크기 체계를 유지한다.
  **예외**: 소스가 이미 16:9 발표 프레임이면 3.5절대로 실측값을 폭 비율로 환산해 쓴다.
  이때 행간 하한 1.4는 그대로 적용하되 64px 이상 대형 헤드라인만 1.2를 허용한다.
- **캔버스는 1280×720(16:9).** pptx 조립(13.333×7.5인치)과 맞춘다.

## 5. 결과 확인

`fig_tokens.py`는 색마다 근거를 함께 출력한다. `이름표 …`면 소스에 적힌 값이고,
`빈도 추정`이면 스크립트가 고른 값이다. **추정으로 잡힌 색은 사용자에게 보여 주고
확인을 받는다.**

생성된 테마 파일 머리말에는 소스에서 가져온 이름 있는 토큰 표가 함께 들어간다.
역할 배정이 마음에 안 들면 그 표에서 값을 골라 1절·4절·6절의 HEX를 바꾼다
(세 곳을 함께 고쳐야 한다 — `SKILL.md` 2단계 참조).

## 6. 이미지가 있는 레이아웃

디코더는 이미지 채움(IMAGE paint) 개수와 내장 이미지 수를 함께 보고한다. 이 값은
소스의 성격을 파악하는 참고용이다. **소스에 든 이미지는 추출하지 않는다.**
발표자료에 넣을 사진·로고를 사용자에게 받는 일은 stitch-ppt 스킬이 맡는다.

## 7. 포맷이 바뀌었을 때

`fig_decode.mjs`가 실패하면 대개 다음 중 하나다.

| 증상 | 확인할 것 |
|---|---|
| `canvas.fig 가 없습니다` | 진짜 Figma 로컬 사본인지. FigJam·다른 앱 파일일 수 있다 |
| 청크가 2개가 아님 | 컨테이너 구조가 바뀐 경우. `header.version`을 확인하고 청크 나열 방식을 다시 본다 |
| 스키마 디코드 실패 | 새 압축 방식이 들어온 경우. 청크 앞 4바이트로 매직을 확인한다(zstd = `28 B5 2F FD`) |
| 노드는 읽히는데 토큰이 빈약함 | 소스에 이름표가 없는 것이다. 빈도 추정으로 잡히므로 사용자 확인을 받는다 |

포맷이 완전히 바뀌어 못 읽으면, 사용자에게 **Figma에서 색·폰트 값을 직접 알려
달라고 요청**하고 `kiwik-card.md`를 복사해 그 값만 손으로 고쳐 테마를 만든다.
억지로 파서를 고치려 들지 않는다.
