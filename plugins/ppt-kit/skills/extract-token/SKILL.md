# extract-token: Figma 로컬 사본에서 디자인 토큰 추출

`.fig`/`.deck` 파일을 받아 그 안에 든 디자인 값을 뽑는다. **토큰 추출까지가 이
스킬의 범위이며 거기서 끝난다.** 뽑은 값으로 슬라이드를 만드는 일은
**stitch-ppt 스킬**이 맡는다.

## 두 가지 경로 — 먼저 어느 쪽인지 정한다

| | 전량 추출 (기본) | 축약 추출 |
|---|---|---|
| 목적 | 파일에 든 값을 하나도 빠뜨리지 않고 뽑는다 | PPT 테마에 필요한 값만 뽑는다 |
| 산출물 | `tokens.raw.json` (원본 대장) | 테마 md 파일 1개 |
| 범위 | 색·타이포·라운드·선·효과·레이아웃·그리드·변수·스타일·컴포넌트·모션 등 A~N | 색 7슬롯 + 라틴 폰트·두께·자간·행간·라운드 |
| 읽을 문서 | `references/full-extract.md` | `references/fig-extract.md` |

**기본은 전량 추출이다.** 용도에 맞춰 미리 줄이지 않는다. 사용자가 "PPT 테마를
만들어 달라"처럼 용도를 명시했을 때만 축약 경로로 간다. 둘 다 필요하면 전량을
먼저 뽑고 그 다음에 축약한다 — 반대 순서로는 버린 값을 되살릴 수 없다.

## 파일 구성 — 무엇을 언제 읽나

| 파일 | 성격 | 읽는 시점 |
|---|---|---|
| `references/full-extract.md` | **전량 추출** — A~N 항목표·출력 규격·자가 점검 | 전량 경로 |
| `references/fig-extract.md` | **축약 추출** — PPT 테마용 7슬롯 배정 규칙 | 축약 경로 |
| `references/themes/kiwik-card.md` | **테마 골격** — 축약 산출물의 형식이자 스크립트의 입력 | 직접 읽을 일은 없다 |
| `references/themes/kiwik.md` | 대체 테마 (여백형). 골격이 아니다 | 필요할 때만 |
| `scripts/fig_decode.mjs` | .fig/.deck → 노드 트리 JSON + 스키마 필드 목록 | 두 경로 공통 |
| `scripts/extract_all.py` | 노드 트리 → A~N 전량 집계 `tokens.raw.json` | 전량 경로 |
| `scripts/fig_tokens.py` | 노드 트리 → 7슬롯 토큰 + 테마 md | 축약 경로 |

`kiwik-card.md`는 **참고 문서가 아니라 스크립트가 런타임에 읽는 골격 파일이다**
(`scripts/fig_tokens.py:38`). `fig_tokens.py`는 이 파일 전문을 읽어 HEX·색 이름·
폰트명·자간·행간을 정규식으로 치환한 결과를 새 테마로 내놓는다. 없으면 스크립트가
`골격 파일이 없습니다`로 중단된다. **임의로 고치거나 옮기지 않는다.**

## 시작 전에 확인할 것

1. 소스 파일이 진짜 Figma 로컬 사본인지 (Figma 메뉴 → File → Save local copy).
   FigJam이나 다른 앱 파일은 읽히지 않는다.
2. 어느 경로인지 (위 표). 사용자가 용도를 말하지 않았으면 전량 추출로 간다.
3. 축약 경로면 만들 테마의 id. 파일명이 되므로 영문 소문자·하이픈으로 받는다
   (예: `acme-blue`).

## 1단계 — 디코드 (두 경로 공통)

먼저 파일을 열어 노드 트리와 **그 파일에 실제로 존재하는 필드 목록**을 뽑는다.

```bash
SKILL="${CLAUDE_PLUGIN_ROOT}/skills/extract-token"
[ -d "$SKILL/scripts/node_modules" ] || npm ci --prefix "$SKILL/scripts"
node "$SKILL/scripts/fig_decode.mjs" <파일.fig|.deck> -o message.json --schema schema.json
```

- `message.json` — 디코드된 노드 데이터 **전문**. 필드를 골라 담지 않으므로 A~N
  원천 값이 전부 여기 있다.
- `schema.json` — `allFieldNames`(실제 필드명) / `enumValues`(타입별 허용값) /
  `definitions`. **필드명을 외워서 쓰지 말고 이 목록 안에서만 값을 뽑는다.**
- `--schema`는 전량 경로에서 필수다. 축약 경로에서는 생략해도 된다.

## 2단계 — 전량 추출 (기본 경로)

집계는 스크립트가 한다. 손으로 `message.json`을 훑지 않는다.

```bash
python "$SKILL/scripts/extract_all.py" message.json -o tokens.raw.json --schema schema.json
```

A~N을 전부 집계해 `full-extract.md` 4단계 규격대로 `tokens.raw.json`을 쓰고,
콘솔에는 항목별 개수·확인 필요·미분류 필드·없던 항목 요약만 찍는다.
`--schema`를 빼면 미분류 필드를 판정하지 못하므로 **전량 경로에서는 반드시 붙인다.**

그다음 `references/full-extract.md`를 읽고 **결과를 검토한다.** 스크립트는 값을 모아
줄 뿐, 토큰 이름을 붙이고(3단계) 추정값을 판정하는 일은 사람이 확인해야 한다.
특히 이런 것은 스크립트가 하지 않는다.

- 이름표 견본 프레임 판독 — 라벨 텍스트와 색 사각형이 한 칸에 있는 구조를 읽어
  이름-값 쌍을 만드는 일. 스크립트는 이름이 토큰 경로 꼴일 때만 `label`로 본다.
- 같은 값이 여러 이름으로 나올 때의 별칭 관계 정리.
- `gradient.angleDeg`(행렬 유도값)와 `lineHeight.ratioBasis`가 `RAW` 해석인 경우의
  타당성 확인.

원칙은 이렇다.

- **버리지 않는다.** 용도에 맞춰 미리 줄이지 않는다.
- **값마다 출처를 적는다.** `variable` / `style` / `label` / `infer` 중 하나이며,
  `infer`로 잡힌 값은 `needsConfirmation`에 다시 모은다.
- **없으면 없다고 쓴다.** 필드가 없으면 `"미확인"`으로 적고 `notFound`에 남긴다.
  그럴듯한 기본값으로 메우지 않는다.
- **단위를 붙인다.** px·%·배수(ratio)·도(deg)를 항상 명시하고, 색은 8자리
  HEX(`#RRGGBBAA`)와 알파 분리값을 함께 적는다.
- 숨김 페인트(`visible=false`)도 버리지 말고 hidden 표시를 달아 포함한다.
- 채팅에는 요약만 적는다. **JSON 전문을 붙여넣지 않는다.**

끝나면 `full-extract.md` 5절 자가 점검을 돌린다. 특히 `notFound`가 빈 배열이면
정말 다 있었는지 의심한다.

## 3단계 — 축약 추출 (용도가 PPT 테마일 때만)

`references/fig-extract.md`를 읽고 그 절차대로 테마 파일을 만든다.

```bash
python "$SKILL/scripts/fig_tokens.py" message.json -o tokens.json --theme <테마id>
```

- `--theme`를 생략하면 토큰만 출력한다. 값을 먼저 눈으로 확인하고 싶을 때 쓴다.
- 테마 파일은 `references/themes/<테마id>.md`에 **이 스킬 폴더 안으로** 생성된다.
  최종 위치가 아니다. 4단계에서 인계한다.
- `fig_tokens.py`는 **색과 타이포만 집계한다.** 효과·그리드·컴포넌트·모션은 손대지
  않으므로, 그 값이 필요하면 2단계 전량 추출을 먼저 한다.

핵심 규칙만 요약하면 이렇다. 자세한 내용은 `fig-extract.md`에 있다.

- **소스에서 가져오는 것**: 색, 라틴 폰트, 글자 두께, 자간, 행간, 라운드. 소스가
  이미 16:9 발표 프레임이면 타이포 위계와 여백·간격 **실측값**까지.
- **소스에서 가져오지 않는 것**: 레이아웃. 소스가 발표자료라는 보장이 없으므로
  골격의 레이아웃을 그대로 두고 스타일만 교체한다.
- **한글 폰트는 항상 Noto Sans KR**로 고정한다. 소스가 다른 폰트를 써도 바꾸지 않는다.
- **행간 하한은 1.4**다. 웹 기준 행간을 그대로 쓰면 슬라이드에서 좁아 읽기 어렵다.
  단 64px 이상 대형 헤드라인은 1.2를 쓴다.
- **크기·간격은 프레임 폭으로 환산한다.** 소스가 1920 폭이면 ×0.667 해서 1280
  기준으로 옮긴다. 원본 px를 그대로 쓰면 전부 1.5배로 커진다.
- 오토레이아웃이 없는 소스는 **노드 좌표를 직접 재서** 여백·거터·행 피치를 뽑는다.
  `fig_tokens.py`는 색만 집계하고 이 계산은 하지 않으므로 손으로 확인한다
  (`references/themes/kiwik-card.md` 2·2.5절이 그렇게 만든 예다).
- **렌더 이미지를 눈으로 보고 짐작한 값은 쓰지 않는다.** 눈으로 본 인상과 파일
  값이 다르면 파일 값을 쓴다.

## 4단계 — 추정값 확인

두 경로 모두, **추정으로 잡힌 값은 반드시 사용자에게 보여 주고 확인을 받는다.**

- 전량 경로 — `tokens.raw.json`의 `needsConfirmation` 목록을 그대로 보고한다.
  `notFound`(찾았지만 없던 항목)도 함께 알린다.
- 축약 경로 — `fig_tokens.py`가 색마다 근거를 출력한다. `이름표 …`면 소스에 적힌
  값이고 `빈도 추정`이면 스크립트가 고른 값이다. 어떤 색이 어떤 슬롯에 갔는지
  알리고, 배정이 틀렸으면 어느 값으로 바꿀지 묻는다.

축약 경로에서 역할 배정을 고칠 때는 생성된 테마 파일의 **1절 색상 표·4절 STYLE
BLOCK·6절 DESIGN.md의 HEX를 함께** 바꾼다. 한 곳만 고치면 사용하는 쪽에서 옛 색이
섞여 나온다. 무엇을 바꿨는지 사용자에게 알려 되돌릴 수 있게 한다.

## 5단계 — 인계

산출물을 넘기고 **이 스킬은 여기서 끝난다.**

- **전량 경로** — `tokens.raw.json`과 `schema.json`을 사용자가 지정한 위치에 두고,
  요약(노드·이미지 개수, 변수/스타일 유무, 항목별 개수, 확인 필요, 찾았지만 없던 것)만
  채팅에 적는다. JSON 전문은 붙여넣지 않는다.
- **축약 경로** — `fig_tokens.py`가 테마를 `~/.claude/ppt-themes/<테마id>.md`에 쓴다.
  **스킬 폴더 안이 아니다.** 플러그인은 버전별 디렉터리에 설치되므로 스킬 안에 쓰면
  업데이트할 때 함께 지워진다. 옮기거나 복사하지 말고 그 자리에 둔다 — stitch-ppt가
  같은 폴더를 본다. 사용자에게 파일 경로와 추출 요약(Primary·Background·TextStrong
  HEX, 라틴 폰트, 행간, 라운드)을 알린다.

  다른 위치에 쓰려면 `PPT_THEME_DIR` 환경변수로 폴더를 지정한다. 그 경우 stitch-ppt를
  실행할 때도 같은 값을 줘야 한다.

사용자가 이어서 PPT를 원하면 **stitch-ppt 스킬**로 넘긴다. **슬라이드 구성안, 화면
생성 프롬프트, pptx 조립은 이 스킬이 하지 않는다.**

생성된 테마 파일에는 stitch-ppt가 쓰는 원형별 프롬프트 블록과 DESIGN.md
본문이 함께 들어 있다. 이 스킬에서는 쓰이지 않지만 **지우지 않는다** — 받는
쪽에서 필요하다.

## 소스를 못 읽을 때

`.fig`/`.deck`은 Figma 비공개 포맷이라 공개 스펙이 없다. 공식 지원 경로가 아니며
어느 날 형식이 바뀌어 깨질 수 있다. 디코더가 실패하면 `fig-extract.md` 7절의
증상별 표를 확인하고, **억지로 파서를 고치지 않는다.** 실패한 지점과 증상을 그대로
보고하고 멈춘다.

필드명이 안 맞기 시작하면 **`schema.json`의 덤프 결과를 기준으로 삼는다.** 문서의
항목표가 아니라 그 파일이 실제로 가진 필드가 정답이다.

포맷이 완전히 바뀌어 못 읽으면 사용자에게 Figma에서 색·폰트 값을 직접 알려
달라고 요청하고, 축약 경로라면 골격 `${CLAUDE_PLUGIN_ROOT}/skills/stitch-ppt/references/themes/kiwik-card.md`를
`~/.claude/ppt-themes/<테마id>.md`로 **복사해** 그 값만 손으로 고쳐 테마를 만든다.
이때도 원본 골격은 건드리지 않는다.

안정성이 중요하면 Figma REST API(파일 링크 + 액세스 토큰)가 공식 경로라고 안내한다.
다만 파일을 직접 주고받는 방식은 아니다.

## 자주 생기는 문제

- `canvas.fig 가 없습니다` → 진짜 Figma 로컬 사본인지 확인한다. FigJam·다른 앱
  파일일 수 있다.
- `골격 파일이 없습니다` → 골격은 **stitch-ppt 스킬**의
  `references/themes/kiwik-card.md`다. `fig_tokens.py`가 자기 위치에서
  `../../stitch-ppt/references/themes/`를 찾으므로, 두 스킬이 같은 플러그인 안에
  나란히 있어야 한다. 스크립트나 스킬 폴더를 따로 떼어 복사해 쓰지 않는다.
- 노드는 읽히는데 토큰이 빈약하다 → 소스에 변수·스타일·이름표가 없는 것이다.
  추정으로 채우지 말고 **"이 파일은 디자인 시스템 파일이 아니다"라고 보고**하고,
  4단계 확인을 특히 꼼꼼히 받는다.
- 청크가 2개가 아니다 → 컨테이너 구조가 바뀐 경우다. `header.version`을 보고한다.
- 청크 디코드 실패 → 새 압축 방식이 들어온 경우다. 청크 앞 4바이트로 매직을
  확인한다(zstd = `28 B5 2F FD`).
- `message.json`이 너무 커서 못 읽는다 → 노드 수에 비례해 커진다. 통째로 읽지 말고
  `extract_all.py`에 맡기고 결과인 `tokens.raw.json`만 읽는다.
- 문서의 항목표에 없는 필드가 나온다 → Figma 버전이 올라간 것이다. `full-extract.md`
  지시대로 **"미분류 필드"로 따로 모아 보고**한다. 무시하지 않는다.
- 모듈을 찾을 수 없다는 Node 오류 → 의존은 `adm-zip`, `fig-kiwi`, `fzstd`,
  `kiwi-schema`, `pako` 다섯 개다. `npm ci --prefix "$SKILL/scripts"`를 실행한다.
  1단계의 부트스트랩 줄과 같은 명령이며, 몇 번을 실행해도 안전하다.
