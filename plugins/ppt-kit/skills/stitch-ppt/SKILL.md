# stitch-ppt: 16:9 한국어 PPT 템플릿 생성

주제나 원고를 받아 16:9 한국어 PPT 템플릿을 만든다. 화면 생성은 Google Stitch가
맡고, 결과 이미지를 pptx로 조립해 전달한다.

각 단계는 독립적으로 쓸 수 있다. 구성안을 이미 갖고 있으면 2단계부터,
이미지를 갖고 왔으면 3단계부터 시작한다.

## 이 스킬이 하지 않는 것 — 디자인 토큰 추출

사용자가 **`.fig` / `.deck` 파일을 주며 "이 디자인으로 만들어 달라"**고 하면,
그 파일에서 색·폰트·간격을 뽑는 일은 **extract-token 스킬이 맡는다.** 이 스킬은
파서를 갖고 있지 않다.

1. extract-token으로 넘겨 테마 파일(`<테마id>.md`)을 받는다.
2. extract-token이 `~/.claude/ppt-themes/`에 써 둔다. **옮기지 않는다** — 이 스킬이
   그 폴더를 함께 본다.
3. 그 테마를 골라 아래 1단계부터 진행한다.

소스 파일 없이 주제만 받았으면 이 절차는 건너뛰고 기본 테마를 쓴다.

## 파일 구성 — 무엇을 언제 읽나

| 파일 | 성격 | 읽는 시점 |
|---|---|---|
| `references/slide-prompts.md` | 원형 9종·슬롯 + BASE BLOCK·조립 규칙(디자인 무관) | 1·2단계 |
| `references/image-slides.md` | 이미지형 슬라이드 — 첨부 이미지 요청·배치 절차 | 1단계 직후, 3단계 |
| `references/themes/*.md` | 내장 테마 — 색·폰트·장식·원형별 프롬프트(디자인 전부) | 2단계 |
| `~/.claude/ppt-themes/*.md` | extract-token이 만든 추출 테마. 같은 형식 | 2단계 |
| `references/stitch-guide.md` | Stitch 조작·내보내기 안내 | 2-2 폴백, 3단계 |
| `scripts/assemble_pptx.py` | 이미지 → 16:9 pptx 조립 | 3단계 |

**디자인에 관한 모든 것은 고른 테마 파일 하나에 있다.**
색을 바꾸든 폰트를 바꾸든 그 파일만 고친다. SKILL.md와 나머지 참고 문서는
디자인과 무관한 뼈대이므로 디자인 변경 때문에 고치지 않는다.

## 시작 전에 확인할 것

사용자에게 다음이 빠져 있으면 먼저 묻는다. 이미 대화에 있으면 다시 묻지 않는다.

1. 발표 주제와 목적(투자 유치, 회사 소개, 제품 소개, 수업 자료 등)
2. 슬라이드 수(모르면 10장 내외를 제안: 표지 1 + 섹션 3 + 본문 5 + 마무리 1)
3. 각 슬라이드에 들어갈 실제 내용(없으면 주제를 바탕으로 초안을 만들어 확인받는다)
4. 적용할 디자인의 소스 파일(`.fig`/`.deck`)이 있는지 — 있으면 extract-token으로 먼저 보낸다

## 디자인 정하기

쓸 테마를 하나 정한다. 테마는 **두 곳**에 있으므로 둘 다 나열해 확인한다.

```bash
ls "${CLAUDE_PLUGIN_ROOT}/skills/stitch-ppt/references/themes/"   # 내장 테마
ls "${PPT_THEME_DIR:-$HOME/.claude/ppt-themes}" 2>/dev/null       # 추출 테마 (없을 수 있음)
```

- **기본은 `kiwik-card`다.** 흰 배경 + 딥그린 강조 + **1px 회색 테두리 카드**.
  라운드 12, 마진 68, 3열 360 + 거터 32. 정보 밀도가 높은 분석·리서치 덱에 맞는다.
- **`kiwik`은 여백형이다.** 카드·테두리를 일절 쓰지 않고 여백으로만 그룹을 나눈다.
  헤드라인이 64px로 크고 한 슬라이드에 3계층까지만 담는다. 여유로운 피치덱에 맞는다.
- extract-token이 만들어 준 추출 테마(`~/.claude/ppt-themes/`)가 있으면 그것을 쓴다.
  같은 id가 양쪽에 있으면 추출 테마가 우선이다.

**한 덱은 한 테마로만 만든다.** 슬라이드마다 섞지 않는다. 특히 `kiwik-card`와
`kiwik`은 카드를 쓰느냐 마느냐가 정반대라 섞으면 바로 티가 난다.

사용자가 "색을 바꿔줘", "다른 느낌으로" 같은 디자인 변경을 요청하면 그 테마 파일만
고친다. 고칠 때는 1절 색상 표뿐 아니라 **4절 STYLE BLOCK과 6절 DESIGN.md의 HEX도
함께** 바꿔야 한다(한 곳만 고치면 슬라이드마다 옛 색이 섞여 나온다). 어떤 값을
바꿨는지 사용자에게 알려 되돌릴 수 있게 한다.

`kiwik-card.md`는 **extract-token의 치환 골격이기도 하다.** 그 파일을 직접 고치기
전에 사용자에게 확인한다. 고치면 앞으로 추출되는 모든 테마가 함께 바뀐다.

## 1단계 — 한국어 슬라이드 구성안

`references/slide-prompts.md` 1부를 읽고, 발표 개요를 슬라이드별 구성안 표로 만든다.

| 번호 | 원형 | 제목(한국어) | 본문 요점(한국어) | 시각 요소 |

- 원형은 반드시 9종 중에서 고른다.
  - 텍스트형 5종: cover, divider, card-grid, split-panel, closing
  - 이미지형 4종: photo-highlight, image-full, image-compare, logo-grid
- **이미지형 4종은 제공받은 콘텐츠에 이미지가 포함돼 있을 때만 쓴다.** 사용자가 사진·로고를
  이미 첨부했거나, 쓸 이미지가 있다고 명시했을 때만이다. 그 외에는 텍스트형 5종으로만
  구성한다. "여기는 사진이 있으면 좋겠다" 싶어서 이미지형을 먼저 배치하고 나중에
  이미지를 요구하지 않는다 — 없는 이미지를 전제로 짠 구성안은 사용자를 불필요한
  준비 작업에 묶고, 이미지를 못 구하면 구성안을 다시 짜야 한다.
- 이미지가 있는지 불확실하면 **이미지형을 빼고 구성안을 만든 뒤**, 표 아래에
  "사진·로고가 있으면 알려 달라, 해당 슬라이드를 이미지형으로 바꾸겠다"고 한 줄 덧붙인다.
- 기본 흐름: cover → divider → 본문 2~3장 → divider → 본문 → closing.
  divider를 본문 2~3장마다 하나씩 넣어 호흡을 만든다.
- 구성안의 내용은 **디자인과 무관하게 재사용된다.** 슬롯 이름이 고정이므로
  같은 구성안으로 프롬프트를 다시 조립할 수 있다.

구성안을 사용자에게 보여주고 확인을 받은 뒤 1.5단계로 넘어간다.

## 1.5단계 — 이미지형 슬라이드가 있으면 첨부 이미지 요청

구성안에 **이미지형 원형이 하나라도 있으면** `references/image-slides.md`를 읽고
그 문서의 요청 양식대로 사용자에게 이미지를 받는다. 1단계 규칙대로라면 이미지형은
**이미 이미지를 받았을 때만** 들어가 있으므로, 이 단계는 보통 받은 파일을 슬라이드에
배정하고 빠진 게 있는지 확인하는 일이다.

핵심만 요약하면 이렇다.

- Stitch에게 사진·로고를 그리게 하지 않는다. 실제 대상과 무관한 합성 이미지가
  나오기 때문이다. Stitch에는 **빈 회색 사각형(플레이스홀더)만** 그리게 한다.
- 2단계 프롬프트를 만들기 **전에** 어떤 슬라이드에 무슨 이미지가 몇 장 필요한지
  표로 알려 주고 파일명을 지정해 첨부받는다(`img-04.png`, `logo-09-1.png` 식).
- 사용자가 이미지를 줄 수 없으면 `image-slides.md`의 대안 3가지를 제시하고
  **선택을 받는다.** 임의로 Stitch 생성 이미지를 쓰지 않는다.

이미지형이 하나도 없으면 이 단계를 건너뛴다.

## 2단계 — Stitch 캔버스에 직접 디자인 생성

`references/slide-prompts.md` 2부와 선택한 테마 파일을 읽고,
슬라이드마다 프롬프트를 하나씩 조립한다.

완성 프롬프트 = **BASE BLOCK**(slide-prompts.md) + **STYLE BLOCK**(테마 4절) +
**원형 블록**(테마 5절) 을 이 순서로 이은 것이며, **줄바꿈 없는 한 문단**이어야 한다.
이미지형 원형이면 맨 뒤에 **PLACEHOLDER BLOCK**(image-slides.md)을 하나 더 붙인다.
`{슬롯}`에는 1단계 구성안의 한국어 원문을 큰따옴표 안에 그대로 넣는다.
자세한 규칙은 `slide-prompts.md` 2부에 있다.

**공통 규칙: 완성된 프롬프트 전문을 채팅창에 나열하지 않는다.** 직접 생성에
성공하면 도구에만 넘기고, 막히면 아래 2-2처럼 문서 파일로 저장한다. 채팅에는
진행 상황과 결과 요약만 짧게 적는다.

### 2-1. 직접 생성 (기본 경로)

사용 가능한 도구 목록에 Stitch 도구가 있으면(공식 Stitch MCP: stitch.googleapis.com,
또는 stitch-mcp / stitch-mcp-auto 같은 프록시 서버의 도구), 프롬프트를 사용자에게
넘기지 말고 그 도구로 Stitch 캔버스에 직접 화면을 생성한다.

1. 프로젝트를 하나 만든다(Web/데스크톱 기준, 16:9 1280×720). 사용자가 기존 프로젝트를
   지정하면 그 프로젝트를 쓴다.
2. 테마 파일 6절의 DESIGN.md 본문을 프로젝트에 등록하는 도구가 있으면 먼저 등록한다.
   없으면 각 프롬프트의 STYLE BLOCK으로 대신한다.
3. 1번 슬라이드부터 순서대로, **같은 프로젝트 안에서** 화면을 하나씩 생성한다
   (한 프롬프트 = 한 화면). 슬라이드마다 새 프로젝트를 만들면 스타일 기억이
   초기화되므로 절대 금지.
4. 화면이 하나 생성될 때마다 "몇 번 슬라이드 완료" 정도로만 짧게 보고한다.
   미리보기 링크나 이미지가 도구 결과로 오면 함께 보여준다.
5. 수정 요청이 오면 해당 화면에만 짧은 수정 지시를 보낸다. 전체 재생성은 하지 않는다.
   단, 요청이 "전체 디자인을 바꿔달라"는 것이면 테마 파일의 색·폰트·장식을
   고친 뒤 새 프로젝트에서 다시 생성한다(위 "디자인 정하기" 참조).
6. 전부 생성되면 이미지 내보내기 방법을 안내하고 3단계로 넘어간다. 도구가 화면
   이미지를 직접 내려받을 수 있으면 받아서 바로 3단계 조립에 쓴다.

### 2-2. 권한이 막힌 경우 (폴백 — 프롬프트를 문서로 저장)

다음 중 하나라도 해당하면 "권한 막힘"으로 판단한다.

- 도구 목록에 Stitch 도구가 아예 없다
- 도구 호출이 인증·권한 오류로 실패한다(401/403, OAuth 미완료, Stitch API 미활성화 등)
- 사용자가 도구 실행 허용을 거부한다
- 사용량(quota) 초과로 생성이 거부된다

이때 **프롬프트를 채팅창에 바로 뱉지 말고**, 아래 구성의 md 문서 한 개로 저장해
파일로 전달한다. 파일명 예: `stitch-프롬프트.md`. 저장 위치는 환경에 맞춘다
(claude.ai는 /mnt/user-data/outputs에 저장 후 present_files로 전달,
Claude Code는 현재 작업 폴더).

문서 구성(위에서 아래 순서):

1. Stitch 수동 조작 순서 요약 — `references/stitch-guide.md`를 읽고 요약
2. DESIGN.md 전문(테마 파일 6절) — Stitch 프로젝트 설정에 등록하도록 안내
3. (이미지형이 있으면) 어떤 슬라이드에 어떤 이미지를 넣어야 하는지 한 줄 안내
4. 슬라이드 번호별 프롬프트 전문 — 슬라이드마다 "복사해서 붙여넣기" 할 수 있게
   코드 블록 하나씩. 코드 블록 안의 프롬프트는 줄바꿈 없는 한 문단이어야 한다

채팅창에는 직접 생성이 막힌 이유와 "프롬프트를 문서로 저장했다"는 안내만
한두 문장으로 남긴다. 문서 내용을 채팅에 다시 복사하지 않는다.

## 3단계 — Stitch 결과 이미지를 16:9 pptx로 조립

사용자가 Stitch에서 내보낸 슬라이드 이미지(PNG/JPG)를 업로드하면:

1. 파일명을 기준으로 슬라이드 순서를 정한다. 순서가 애매하면 사용자에게 확인한다.
2. `scripts/assemble_pptx.py`를 실행해 16:9(12192000×6858000 EMU, 즉 13.333×7.5인치)
   pptx를 만든다. 이미지는 슬라이드에 꽉 차게 배치되고, 비율이 다르면 여백 없이
   중앙 크롭된다.

```bash
SKILL="${CLAUDE_PLUGIN_ROOT}/skills/stitch-ppt"
pip install python-pptx Pillow --break-system-packages  # 없을 때만
python "$SKILL/scripts/assemble_pptx.py" <이미지폴더> -o 발표자료.pptx
python "$SKILL/scripts/assemble_pptx.py" <이미지폴더> -o 발표자료.pptx --notes notes.txt
python "$SKILL/scripts/assemble_pptx.py" <이미지폴더> -o 발표자료.pptx --overlay <첨부폴더>/overlay.json
```

3. **1.5단계에서 이미지를 받았으면** `references/image-slides.md`의 규격대로
   `overlay.json` 배치표를 만들어 `--overlay`로 넘긴다. 회색 플레이스홀더 자리에
   사용자 이미지가 얹힌다. 원형별 기본 `box` 값과 프리셋 목록은 그 문서에 있다.
   만든 뒤에는 플레이스홀더가 완전히 덮였는지, 글자가 가려지지 않았는지 확인한다.
4. 발표자 노트가 필요하면 1단계 구성안의 본문 요점으로 `notes.txt`를 만들어
   (슬라이드마다 `---` 구분) `--notes`로 넘긴다.
5. 완성된 pptx를 사용자에게 전달한다. 한국어가 깨진 슬라이드가 있으면,
   해당 슬라이드만 이미지 위에 pptx 텍스트 상자를 얹어 교체하는 방법을 제안한다
   (이때는 pptx 스킬의 편집 방법을 따른다).

## 자주 생기는 문제

- Stitch가 16:9가 아니라 세로 화면을 만든다 → 프롬프트 맨 앞의 BASE BLOCK이
  빠졌는지 확인한다. Web 모드인지도 확인한다(App 모드는 모바일 비율로 나온다).
- 슬라이드마다 색이 조금씩 다르다 → DESIGN.md를 프로젝트에 등록했는지 확인하고,
  같은 프로젝트 안에서 화면을 추가로 생성하게 안내한다(새 프로젝트를 만들면 스타일이 초기화된다).
- 색을 바꿨는데 일부 슬라이드만 옛날 색이다 → 테마 파일 1절 표만 고치고
  STYLE BLOCK·DESIGN.md의 HEX를 안 고친 경우다. 그 파일 안의 해당 HEX를 전부 찾아 바꾼다.
- 카드에 그림자가 생긴다 → `kiwik-card`는 그림자를 쓰지 않는다(원본 `effects` 0건).
  해당 화면에만 "Remove all drop shadows; separate cards with a 1px #A3A3A3 border only."
  라고 짧게 수정 지시를 보낸다.
- 카드가 배경과 구분되지 않는다 → `kiwik-card`는 카드 배경이 슬라이드 배경과 같은
  흰색이고 **테두리로만 구분한다.** 배경색을 넣지 말고 테두리가 그려졌는지 확인한다.
- 플레이스홀더 자리에 Stitch가 사진을 그려 넣었다 → 해당 화면에만
  "Replace the image area with a plain flat light-gray rectangle, no picture inside."
  라고 짧게 수정 지시를 보낸다. PLACEHOLDER BLOCK이 프롬프트 맨 뒤에 있었는지도 확인한다.
- 첨부 이미지가 글자를 가린다 → 원형 블록이 글자를 이미지 영역 위에 두고 있다는 뜻이다.
  `overlay.json`의 `box`를 글자 영역 밖으로 줄이거나, 테마 파일의 해당 원형 블록에서
  글자 위치를 이미지 밖으로 옮긴다(`image-slides.md` 참조).
- 로고가 잘리거나 찌그러진다 → `overlay.json`에서 `"fit": "contain"`을 썼는지 확인한다.
- 한국어 글꼴이 이상하게 나온다 → 프롬프트에 지정된 한국어 폰트
  (예: "Noto Sans KR")가 들어 있는지 확인한다.
- 직접 생성이 도중에 실패한다 → 인증 만료나 사용량 초과일 수 있다. 같은 호출을
  한 번만 재시도하고, 또 실패하면 권한 막힘으로 판단해 2-2 폴백(문서 저장)으로
  전환한다. 이미 생성된 화면은 그대로 두고 남은 슬라이드 프롬프트만 문서에 담는다.
- `.fig` 파일을 받았다 → 이 스킬은 파서가 없다. extract-token 스킬로 넘긴다. 테마는
  `~/.claude/ppt-themes/`에 생기며, 옮기지 않고 그대로 골라 쓴다.
- 추출 테마가 목록에 안 보인다 → extract-token이 `PPT_THEME_DIR`를 지정해 실행됐는지
  확인한다. 그렇다면 이 스킬도 같은 값을 준 상태로 실행해야 한다.
